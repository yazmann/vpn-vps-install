# Выпуск версии

## Когда создавать релиз

Создавайте обычный релиз после изменений, проверенных GitHub Actions и на чистом VPS. Если реальный smoke-тест ещё не выполнен, публикуйте версию только как GitHub Pre-release.

## Нумерация

- `v1.0.0` — первая стабильная версия после нескольких успешных реальных установок.
- `v1.0.1` — исправления без новых возможностей.
- `v1.1.0` — новые возможности с сохранением совместимости.
- `v2.0.0` — изменения, требующие другого порядка установки или несовместимые с прежними настройками.

## Перед выпуском

- [ ] Проверить Pull Request: Bash syntax и ShellCheck.
- [ ] Установить standalone-сервер на чистом Ubuntu VPS с доменом.
- [ ] Проверить удалённую ноду.
- [ ] Проверить AmneziaWG с актуальным клиентом. Подтвердить подключение, DNS, IPv4, сетевую политику, сохранение ключей при восстановлении и удаление правил UFW/NAT.
- [ ] Проверить Hysteria 2 с внешней сети. Сравнить сайт по HTTPS и HTTP/3, проверить неверную аутентификацию, правильный и чужой SNI, обновление сертификата.
- [ ] Перенести пользователей из SQLite-бэкапа в свежую панель. Проверить UUID, subId, лимиты, израсходованный трафик и откат при сбое.
- [ ] Импортировать зашифрованные ссылки в HAPP и INCY. Повторить установку с выключенным шифрованием и обычным HTTPS URL.
- [ ] Проверить WARP: российские домены (.ru/.su/.рф и category-ru) и IP (geoip:ru) через WARP, остальные направления по обычным маршрутам. При отказе WARP совпавший трафик не уходит напрямую. Проверить актуальность geodata, прямые обращения по IP, российские сервисы в других доменных зонах и приоритет над явным direct; API и блокирующие правила должны сохраняться.
- [ ] Проверить фактический VLESS-трафик и WARP trace; на ноде сначала выдать клиента из главной панели.
- [ ] Прервать установку на стадии пакетов, сертификата и Nginx, затем проверить возобновление.
- [ ] Проверить удаление с добавленными посторонними файлами и отказ для установки без журнала.
- [ ] Проверить просмотр настроек, восстановление и полное удаление.
- [ ] Проверить ежедневные исправления безопасности, воскресное полное обновление в 05:30 и условную перезагрузку после обновлений.
- [ ] Обновить [CHANGELOG.md](CHANGELOG.md).
- [ ] Убедиться, что в коммитах и файлах нет секретов.

## Публикация

1. Создайте Draft Release в GitHub.
2. Создайте SemVer-тег на проверенном коммите `main`. Проверьте, что инструкция установки в README указывает на этот тег.
3. Добавьте краткие release notes: новые возможности, исправления и известные ограничения.
4. Опубликуйте релиз только после финальной проверки текста и файлов.

GitHub Release фиксирует конкретный тег и позволяет пользователям установить проверенную версию, а `main` оставить для актуальной разработки.
